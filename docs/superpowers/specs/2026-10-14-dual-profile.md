# Dual Profile design
User-authorized direct implementation. Kotlin/Compose Material3 DPC, package com.dualprofile.app; SDK 36/36/28. Personal A and single managed Work B. No Knox SDK, private API, bypass, runtime shell, notification proxy or APK modification.
Profile owner initialized idempotently by protected provisioning callbacks. Personal verifies Work owner by authenticated companion response, never RESULT_OK. Public cross-profile intent filter targets disabled-in-Personal bridge. Shared random pairing key travels through provisioning admin extras; HMAC, timestamp and nonce authenticate commands and results. FileProvider read grants convey unchanged base and splits; digests protect payload. Work PackageInstaller sessions preserve package/version/signature, expose policy failures and resolved stores. installExistingPackage requires actual affiliation and owner.
Main list includes only structurally safe launcher packages with verified Work capabilities. Work queries confirm installation. Quiet mode uses UserManager with Settings fallback. No inaccessible One UI/Knox version claims. Debug APK plus independent probe APK for data/notification and split tests. Physical validation requires connected SM-A576B; unattended provisioning clicks prohibited.

Follow-up user-requested custom APK permissions: explicit owner-scoped Work consent screen removes only this admin’s local unknown-source restriction; never auto-mutates, never clears global/install-apps/other-admin/OEM protections. Source permission handled in normal Android Settings by user. Route authenticated; Activity nonexported. Store and APK actions labelled distinctly. Debug lawful Probe can reach OS for diagnostic without local unknown-source preflight, while OS enforces policy.
